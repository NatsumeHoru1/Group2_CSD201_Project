# Đoạn cho mục Methods: "Correctness verification" (viết bằng tiếng Anh, ~0,15 trang)

Chỉ giữ những câu đúng với bằng chứng nhóm có; xóa câu nào chưa thực hiện thật.

> **Correctness verification.** Every implementation is checked by a self-contained test harness (no external framework) before any measurement. First, a differential oracle replays 10^6 random operations (40% put, 40% get, 20% remove) against `java.util.HashMap` on a table of M = 2^12 cells, over three key domains of about 0.5M, M and 2M keys; the harness checks every return code, including `FULL` (expected exactly when the table holds M keys and the key is absent, in which case data must be unchanged), compares the size after each operation, sweeps the whole key domain periodically, and calls each implementation's invariant checker where available. Second, small-table cases on M = 16 cover reserved-value rejection, a full table, termination of absent lookups on a full table, clusters that wrap around from the last cell to the first (deleting each member in turn), and 20,000 delete–insert steps at loads of 8/16 and 14/16. Third, the workload generator and the control table are validated by checking that the aged table and a freshly built table over the same live keys return identical `output_check` values. The harness itself was validated by mutation: four deliberately faulty tables were all rejected. These tests establish functional agreement with the reference map; they do not by themselves prove the probe counts or timings reported later.

**Bằng chứng cần giữ (để mọi câu truy được):** log chạy `tv4_test.bat` (kèm hash commit và `java -version`), danh sách seed trong `AllTests`/`OracleTest`.
**Hạn chế phải ghi vào Threats to Validity:** oracle chỉ chạy ở M = 2^12, không phải 2^20; `put` bị cấm với `Integer.MIN_VALUE`.
